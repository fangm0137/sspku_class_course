第3课 认证授权与知识库入库
从规约实现 CampusClaw 迭代1的操作讲义

本课接着第2课的同一份 OpenSpec 变更，实现可登录、可按班级隔离、可上传并保存知识正文的系统，再用 Docker Compose 交付。完成条件包括可运行代码、逐条验证证据、设计决策和归档后的长期规约。

本讲义依据原站19个教程页面整理，用自己的语言解释操作过程，保留课程要求和来源入口；不是录课逐字稿，也不是原始PPT。标有“补充解释”“操作示例”“建议”的部分是整理时增加的执行说明。提取日期为2026年9月25日。

这次如何照着做
每一步现在都分为解释、实施提示词、核对提示词和命令示例。先读要求，再把该步提示词发给编程工具；让它只实现一小项，执行verify后再继续。

三种内容的标识： “课程命令”保留必要的命令名称和参数；“按课件要求重写的提示词”保留要检查的事项但重新组织表述；“补充代码/测试示例”是为方便操作新增的例子，不冒充原课件源码。原站第3课没有提供完整应用代码，不能把下面的局部代码当成已经可以直接启动的整仓库。

执行位置： /opsx-... 发到编程对话框；PowerShell命令在项目终端执行；SQL在测试数据库客户端执行；代码块按其标出的文件位置保存。实际change名、用户、端口、数据库名、材料ID以及尚未确定的接口字段，都要与自己的项目一致。

1 开工前先确定范围和技术栈
1.1 本课做什么
教师、学生使用账号密码登录，系统能够判断用户、角色及所属班级。
教师上传本班的文本材料；学生只读本班材料，可以查看和下载。
列表、详情、下载和上传都受服务端权限约束。
文件保存后提取正文，形成材料记录和知识库记录；列表重新查库能看到结果。
第三方可按 README 在本机用 Compose 启动，验证后完成 OpenSpec 归档。
这里的“知识库入库”只指保存可查询正文和来源关联。它不等于向量化、全文检索或 RAG 问答；后续智能能力不在这次迭代内。

1.2 本课不做什么
当前教程排除：向量检索和问答、对话助手、作业批改与成绩错题流程、JWT/OAuth/SSO、注册改密、短信邮箱登录、多校复杂租户、PDF/Word/图片解析、在线编辑、Kubernetes、多副本高可用、公网域名和HTTPS发布流程。平台超级管理员也不在本迭代，应另开变更设计跨班权限及审计。

补充解释： 这些是本课程迭代范围，不是说上述方案在其他系统中都不合适。浏览器里的 Markdown 正文展示仍属于本课；不要把“暂不做复杂文件预览”理解成不需要展示文本详情。

1.3 第2课样板不能不加修改地混进来
项目	第2课常见样板	第3课教程采用
页面与应用	Flask与模板页面	React 18 TypeScript Vite前端 与Go API
数据库	SQLite	MySQL 8.0
对外入口	单个应用服务	Nginx提供静态资源并反向代理
登录态	Flask会话示例	服务端会话表加不透明Cookie ID
跨班对象访问	403或404择一	404，与不存在的记录对外同形
health	第2课示例曾提及可选查库	第3课明确只表示进程存活
如果自己的规约还写着 Flask/SQLite，却准备跟随第3课教程做 Go/MySQL，先修改当前 change 的 design、delta 和 tasks，使它们一致。教程也允许基于自己的规约解释其他实现路线，但不能让文件写一种、代码做另一种。

来源页面：要做成什么样、系统怎么走、安全与部署、认证方案对照。

2.2 Apply 前必须能找到的四条约定
未登录访问不能带出材料标题、正文或文件路径。

4 第二步 建数据结构和种子
目标： 让后续权限测试有真实、可辨认、能重复初始化的数据。

4.1 先设计五张关键表
表	需要表达的信息	关键约束
classes	班级标识与名称	能区分A班和B班
users	用户名 密码哈希 角色 班级	角色受限，班级关联明确
sessions	会话与用户关联 有效期	能找到用户并判断是否过期
materials	标题 上传者 班级 原文件存储信息	class_id非空并建索引
knowledge_entries	材料关联 班级 正文 来源	class_id非空并建索引，关联正确材料
第2课还要求的讲义、作业、助手、技能等占位结构，如果仍在自己的规约中，就不能因本页重点讲五张表而默默取消。需要调整时，应先正式修改 delta 并说明原因。

4.2 准备足够区分的种子
班级：A、B。
账号：teacher_a 归A班，student_a1 归A班，student_b1 归B班。
材料：两个班至少各一条，标题要明显可分，例如分别含A班和B班标识。
知识正文：样本材料对应正文记录，便于查验关联和隔离。
密码：从环境取得，再用 bcrypt 等规约选定的密码哈希算法处理后入库。
4.3 让初始化可以重复运行
重复初始化不能复制账号、复制材料或覆盖教师后来上传的内容。可采用唯一约束加适当的插入逻辑，具体机制在 design 中说明。不能靠“记住只执行一次”代替幂等性。

4.4 分清两类查询
列表按可信的会话班级查询。对象详情和文件下载在教程中采用“按ID取记录，再检查所属班级”的流程，检查通过后才能输出任何内容或打开文件。

补充解释： 这是一种课程选定的实现方式；一般工程中，将ID和可信班级同时放进查询条件也可以实现安全隔离。关键是行为与规约一致，并且不存在任何绕过检查的输出路径，不能把教程对具体流程的选择当成普遍唯一正确写法。

4.5 本步怎么验
查表结构，确认材料和知识记录的班级字段非空、有索引。
查询三账号的角色及归属；查看密码字段形态，不能等于测试账号明文密码。
连续执行两次初始化，对比用户、材料、知识记录数量和内容，确认未复制或覆盖。
分别按A班和B班查询，确认结果及标题可区分。
完成产物： 建表或迁移、幂等种子、数据访问层，以及可复核的查询结果。

5 第三步 实现登录和服务端会话
目标： 证明请求者是谁，为角色权限和班级隔离提供可信上下文。

5.1 认证 授权 隔离分开理解
认证确认“是哪一个用户”；授权判断“这个角色能否执行上传”；隔离判断“这个用户能否访问这条材料所属班级”。登录成功不等于可以查看所有班级或调用所有功能。

5.2 实现登录
POST /api/login 接收登录信息，按接口约定做输入检查。
查询用户，使用密码哈希库验证输入密码，不自行比较明文。
成功后生成新的不可预测会话ID，保存服务端会话，并使登录前沿用的旧会话失效。
将不透明ID放入 Cookie；浏览器不接收可自行指定权限的可信角色载荷。
会话检查时在服务端得到用户标识、角色和班级。教程总表澄清：可以让会话表存 user_id，角色和班级每次联表读取，不必把三项都物理复制进会话行。
5.3 设置 Cookie 并处理过期
教程使用 HttpOnly、SameSite=Lax，在本机HTTP实验中不强制 Secure。会话要有有效期，过期或无效会话不能继续访问。

补充解释： 本地HTTP设置不应直接当作公网配置。HttpOnly 限制脚本读取Cookie，但不能单独解决所有XSS或CSRF；这里记录的是同源课堂应用的选择。

5.4 增加认证中间件和身份接口
受保护API首先读取Cookie并核验会话；不存在、无效或过期时返回401，不返回标题、正文、路径。GET /api/me 给已登录前端提供当前用户、角色和班级。角色未知时不能按教师权限放行。

数据库故障必须与“会话确实无效”区分。无法查询数据库的业务请求按教程返回503，而不是把用户误判成未登录并返回401。

5.5 实现真正的登出
POST /api/logout 删除服务端会话并清除Cookie。验收时保留登出前的旧Cookie，再拿它访问材料接口，必须得到401。只清浏览器界面状态、旧Cookie仍有效，不算登出完成。

5.6 统一失败并限制重试
教程要求“不存在的账号”“密码错误”“处于限流状态”的对外失败响应尽量一致，用户名与IP组合用于失败限流。账号不存在时也做等价的哈希计算，避免明显时间差；锁定期内即使密码正确也拒绝。

补充解释： 不同系统可能采用429等限流语义；本课采用统一失败策略，需要写进自己的规约。几次耗时测试只能查明显差异，不能证明完全不存在计时侧信道。

5.9 密码哈希补充代码示例
下面演示调用bcrypt库，不是原课件的完整后端源码。可位于 backend/internal/auth/password.go，依赖版本应由项目的go.mod/go.sum管理。会话、中间件和限流仍需要另外实现。函数用法参见Go bcrypt文档。

Go · 补充局部代码
复制
package auth

import "golang.org/x/crypto/bcrypt"

func HashPassword(plain string) (string, error) {
    encoded, err := bcrypt.GenerateFromPassword([]byte(plain), bcrypt.DefaultCost)
    if err != nil {
        return "", err
    }
    return string(encoded), nil
}

func VerifyPassword(encoded, plain string) bool {
    return bcrypt.CompareHashAndPassword([]byte(encoded), []byte(plain)) == nil
}
理解两处调用： 种子或创建账号时调用HashPassword；登录时将库里的哈希交给VerifyPassword。不要在登录时重新生成哈希再比较字符串，因为每次盐不同，结果不应相同。未知账号分支的等价耗时处理、输入限制和失败响应不由这两个函数自动完成。

校验失败：不创建持久文件和记录。

第一张表写入后第二张失败：回滚整个数据库事务。

9.4 写好health语义
GET /health 不要求登录，正常返回200并说明进程存活。按第3课选择，它不查询数据库。数据库停用时，业务API应返回503，health仍可报告进程可响应。

补充解释： Compose的healthcheck通常提供健康状态；不能把“标记unhealthy”直接等同于一定自动重启。是否重启还受运行方式和其他管理策略影响。

9.9 Nginx补充配置示例

server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    location /api/ {
        proxy_pass http://api:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_pass http://api:8080;
    }

    location /uploads/ {
        return 404;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

function Invoke-CourseRequest {
    param(
        [string]$Method = 'GET',
        [string]$Path,
        $Session,
        [string]$Json,
        [hashtable]$Form
    )
    $requestOptions = @{
        Uri = "$BaseUrl$Path"
        Method = $Method
        SkipHttpErrorCheck = $true
    }
    if ($Session) { $requestOptions.WebSession = $Session }
    if ($Json) {
        $requestOptions.ContentType = 'application/json; charset=utf-8'
        $requestOptions.Body = $Json
    }
    if ($Form) { $requestOptions.Form = $Form }
    $response = Invoke-WebRequest @requestOptions
    [pscustomobject]@{
        Method = $Method
        Path = $Path
        Status = [int]$response.StatusCode
        Body = $response.Content
    }
}

function Connect-CourseUser {
    param([string]$UserName)
    $securePassword = Read-Host "$UserName 的本地测试密码" -AsSecureString
    $credential = [pscredential]::new($UserName, $securePassword)
    $loginJson = @{
        username = $UserName
        password = $credential.GetNetworkCredential().Password
    } | ConvertTo-Json
    $webSession = [Microsoft.PowerShell.Commands.WebRequestSession]::new()
    try {
        $login = Invoke-CourseRequest -Method POST -Path '/api/login' -Session $webSession -Json $loginJson
        if ($login.Status -lt 200 -or $login.Status -ge 300) {
            throw "登录失败，HTTP $($login.Status)；核对凭据、限流和请求字段。"
        }
        return $webSession
    } finally {
        $loginJson = $null
        $credential = $null
        $securePassword = $null
    }
}

13 排错时按哪条线查
症状	优先检查
登录成功后一刷新就退出	Cookie作用域和属性，代理是否同源，会话是否存在，/api/me结果
学生页面无按钮但上传成功	后端上传入口是否真正检查可信role
列表隔离但下载跨班成功	文件handler是否独立核验归属，是否暴露静态uploads
上传成功但刷新后消失	是否仅改前端状态，数据库事务是否提交，列表是否查同一数据库
有材料行但没有正文	两表是否真正共享同一事务，错误是否被忽略
上传报错后目录越来越大	失败分支是否执行文件清理
每次启动多出账号	种子幂等性和唯一约束
容器重建后数据丢失	卷挂载是否正确，是否误用了down -v，数据是否写到容器临时层
首次启动502不恢复	MySQL就绪等待，api启动日志，Nginx目标地址和端口
数据库停用后被送回登录页	是否把数据库错误误映射成401，前端是否把503当会话失效
validate过了但系统不安全	是否遗漏了真正执行的负向Scenario
如果是规约含糊，先修改delta；如果代码违反已有Scenario，引用条款修代码；如果是环境问题，按README重现并定位。三类问题不要都靠随口追加新需求处理。

14 原站表述差异与使用边界
提交组织： 课程首页说明分组项目，第3课教程强调个人独立完成和提交。二者有差别，需按教师当前要求确认；不能仅凭讲义擅自认定。
会话保存位置： 认证和总表的具体说明为MySQL服务端会话；Compose部分有“会话和限流在内存”的概括。以明确的会话设计为准，可将限流状态保留在单实例内存，但不要据此删除会话表。
界面范围： 演示R10列出完整体验项目，个人规约范围页允许未纳入的项目可选。实现前固定自己的版本和要求。
证据数量： 原页既有两条最低留证，又有三条各留证。建议覆盖三条关键失败路径。
课程示例不是通用定律： 404、Cookie、fetch-then-check和单实例都是本教程的选择。JWT不是天生不安全，带班级条件的对象查询也并非天然错误；更换方案需要重新论证和更新相应Scenario。
测试范围： 本讲义解释了要怎样实现和验收，没有声称实际完成你的项目。命令参数、字段名和限额应与你的规约一致。
