# Proposal

## Why

CampusClaw 需要先建立班级教学材料的可信访问边界：教师上传后，同班成员可复用，其他班级不可读取。当前仓库仅有项目说明及 OpenSpec 配置，尚无应用实现；本变更为第2课形成可评审、可验证的实现合同。

## What Changes

- 教师、学生使用账号密码登录，采用 MySQL 服务端会话表与不透明 Cookie ID，支持身份查询及登出吊销；所有材料及知识库数据入口要求有效身份。
- 增加匿名可访问的 `GET /api/csrf`，向匿名或已登录会话下发绑定的写请求保护令牌；统一接口响应字段与安全错误格式。
- 服务端根据可信账号记录确定角色与班级；仅教师可为自己的班级上传，直接调用接口的学生同样被拒绝，客户端班级参数不能扩大权限。
- 支持 UTF-8 txt/md 教学材料：保存原文件、提取文本，并创建关联的材料与知识库记录；成功后本班教师和学生刷新列表即可看到，其他班级不可读取。
- 定义登录、上传、列表、读取、失败回滚及跨班级拒绝的验收条件。
- T1.2 采用显式版本化 SQL 迁移；材料与知识库均保存非空且有索引的 class_id，通过复合外键确保班级一致；迁移不生成种子数据。当前规约无额外占位表要求。
- 采用 Go + MySQL 8.0 + React 18 TypeScript Vite + Nginx；密码仅保存带盐哈希，会话索引摘要密钥从环境注入；规划 Docker Compose、仅表示进程存活的匿名 `GET /health`、数据库及文件持久化。数据库故障由业务接口返回 503，health 不查库。
- 规划 A/B 两班、教师 A、学生 A1、学生 B1 和具有不同内容标记的材料样本，用于验证授权边界与重启后数据保留。
- 本轮只生成 OpenSpec 文档；所有实现与 verify 任务保持未勾选，不生成应用代码或启动 Compose。

## Capabilities

### New Capabilities

- `class-material-access`: 账号登录、教师/学生权限、服务端班级隔离、材料上传入库与读取，以及本地运行和验收数据约定。

### Modified Capabilities

无。当前主规约目录没有既有能力规约。

## Impact

后续实现涉及认证与授权中间件、账号/班级/会话（sessions）/材料/知识库数据模型、受保护的材料 API 与最小页面、文件存储、部署配置和集成验收。拟新增密码哈希、数据库和 HTTP 服务依赖；具体方案见 design.md。本轮无业务代码、数据库迁移或运行环境变更。

## Non-goals

不做问答、聊天、作业流程（含布置、提交、批改）、注册与密码找回、SSO、生产高可用；不引入课表练习、向量检索或模型调用。知识库入库在本变更中指持久化提取文本及其材料关联。

本迭代也不做并发初始化、种子中途失败补偿、登录限流、分页、总存储配额、文件清理持续失败的自动重试策略，以及上传去重/幂等键。正常串行重复初始化的幂等性、上传确定失败的回滚与一次补偿清理仍在范围内。持续清理失败时保持业务未就绪并报告安全错误，待人工处理；health 仍仅表示进程存活。
