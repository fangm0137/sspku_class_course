# 个人项目能力补齐：多 AI 应用、提示词模板、技能上传、MCP 工具与模型调用审计

## Why

个人项目的验收要求平台至少具备五项能力：内置多个 AI 应用、提示词模板、知识库检索、内置技能并支持上传、外部工具与 MCP 接入；同时要就"每次对话究竟把什么发给了模型"给出五项可核对的回答（完整请求参数与响应、模板是否随请求发送、知识库是否全量传入、技能内容传入多少、技能的执行逻辑、接入 MCP 后请求参数有何变化）。

仓库在第 3–5 课已具备：登录与班级隔离、材料入库与三模式检索、智能体与技能路由、SSE 流式回答。**仍缺**四项能力，且缺一个能直接回答上述五问的证据来源：

| 要求 | 现状 |
|---|---|
| 内置多个 AI 应用 | ❌ 智能体只能由教师手工创建，没有任何预置应用 |
| 提示词模板 | ❌ 提示词是自由文本字段，没有模板、占位符与复用 |
| 知识库检索 | ✅ 已有（`knowledge-retrieval`、`knowledge-qa`） |
| 内置技能 + 上传技能 | ⚠️ 内置 ✅；"上传"只接受 JSON 里的原文，没有文件上传入口 |
| 外部工具与 MCP | ❌ 完全没有 |
| "发给模型什么"的证据 | ❌ 请求体不落库，只能靠读代码推断 |

因此本变更补齐这四项能力，并把**每一次模型调用的请求体与响应完整落库**，让五项验证都能用运行结果回答，而不是用说明文字。

## What Changes

- **提示词模板**：新增 `prompt_templates`，模板体支持 `{{app_name}}`、`{{today}}`、`{{question}}` 三个占位符。服务端渲染后把**渲染结果**作为系统消息首段发送；模板编号与模板原文本身不进入请求体。
- **AI 应用**：`tutor_agents` 增加 `prompt_template_id` 与 `builtin_key`。预置三类内置应用（数学助教、语文助教、通用答疑），以 `builtin_key` 幂等初始化，可启停、可改绑定，但内置身份不允许被冒名重复创建。
- **技能上传**：新增 `POST /api/skills/upload`（multipart），与既有 JSON 创建共用同一套解析、长度与工具校验；错误仍带行号。
- **MCP 与外部工具**：同仓新增 `mcp-server/`（JSON-RPC 2.0 单端点，`initialize` / `tools/list` / `tools/call`，Bearer 鉴权，两个工具），由 Compose 一并构建启动；主机侧新增 `mcp_servers` 与 `mcp_tools`，支持登记、连接（握手 + 工具发现并**整体替换**缓存）、断开（清空缓存）、删除。技能「工具」字段除 `knowledge_search` 外支持 `工具名@服务器名`。
- **工具调用循环**：每次提问把本轮候选集（由命中技能决定）转换为 `tools` 声明随请求发送；模型返回结构化调用后，宿主按声明中的输入结构校验参数、带令牌执行 `tools/call`，结果以 `role:"tool"` 消息回传并再次请求模型，可循环多轮，受轮次与单轮次数上限约束，超限后优雅降级。
- **模型调用审计**：新增 `llm_calls`（每次调用一行，含完整请求体、响应、轮次、状态、耗时、token 用量）与 `tool_calls`（工具引用、状态、轮次、用户、会话、时间）。教师可在页面查看每次调用的请求与响应原文。
- **前端**：新增「AI 应用」「提示词模板」「MCP 工具」「调用审计」四个视图。

## Capabilities

### New Capabilities

- `ai-apps`：内置应用与应用的组成（模板 + 技能 + 材料 + 工具），以及应用之间的独立性。
- `prompt-templates`：模板的增删改查、占位符语法、渲染口径与失败行为。
- `skill-library`：内置技能清单与技能文件上传、校验与准入。
- `mcp-tools`：MCP 服务器的登记与连接生命周期、工具发现与缓存、技能引用、带令牌调用与失败语义。
- `llm-call-audit`：每次模型调用的请求/响应留痕，以及五项验证所需的可查询字段。

### Why no MODIFIED delta

本变更**不修改任何既有能力的既有需求**，全部以新增能力表达。原因有二：

1. 第 5 课的能力（`tutor-agents`、`agent-skills`、`conversations`、`streaming-answers`）目前仍是**活动变更**，尚未归档为主规约；此时对它们写 MODIFIED 会指向一个还不存在的基线。
2. 本变更对既有行为的扩展都是纯叠加：模板为空时回落自由文本、工具字段多接受一种引用形态、`meta` 事件多一个字段。这些在 `ai-apps`、`mcp-tools`、`llm-call-audit` 里以 ADDED 需求写出，归档时与主规约合并即可，不存在语义冲突。

## Impact

- **数据**：迁移 `000006` 新建 `prompt_templates`、`mcp_servers`、`mcp_tools`、`llm_calls`、`tool_calls`，并给 `tutor_agents` 增加两列（含同班复合外键与内置唯一键）。
- **接口**：新增模板 CRUD（4 条）、技能上传（1 条）、MCP 管理（6 条）、审计查询（2 条）；`POST /api/conversations/{id}/messages` 的 `meta` 事件增加 `tool_calls` 字段。
- **部署**：Compose 增加 `mcp` 服务与 `MCP_AUTH_TOKEN`；`nginx.conf` 不变（MCP 只走服务端内网）。
- **文档**：新增 `backend/MCP.md` 与 `backend/AUDIT.md`；`/openapi.yaml` 同步。
- **兼容性**：`prompt_template_id` 可为空，为空时沿用原"自由文本提示词 + 默认角色回退"行为，第 3–5 课的既有场景不受影响。

## Non-goals

- **不做通用工具编排**：候选集只来自技能声明的 `工具名@服务器名`，不提供"把本班全部工具一次性交给模型"的开关；也不做跨技能的多技能协同。
- **不做写操作的人工确认**：本迭代只接入只读工具；写入类与数据外发类工具的人工确认（human-in-the-loop）留到后续。
- **只实现 MCP 的 tools 一类能力**：不实现 `resources` 与 `prompts`；也不做 `stdio` 传输，只走 Streamable HTTP。
- **可观测性只做到日志层**：每次调用一条记录；聚合指标（成功率、耗时分布）与多轮链路追踪不做。
- **不做第三方应用商店**：内置应用只在初始化时写入，不提供跨班级共享或导入导出。
- **不做提示词的版本历史**：只保留当前版本，不记录修改前后的快照。
- **不把审计用于计费**：`llm_calls` 记录网关返回的用量，但不做配额、限额或账单。
- **不改造既有检索与问答口径**：`GET /api/search`、`POST /api/ask` 的行为与错误语义保持第 4 课定义不变。
