# Design

## Context

动机见 proposal.md。已检查 README、AGENTS.md、OpenSpec 配置与目录：当前没有业务源码、测试、部署文件或主规约；README 已指向本变更目录。本轮仅规划，以下均为后续实现决策，不代表已实现或已验证。

## Goals / Non-Goals

**Goals:** 在单机课堂演示中形成登录、可信授权、上传入库、同班读取的完整闭环，并能通过 API 直接验证，权限不依赖页面按钮。

**Non-Goals:** 沿用 proposal 的排除项：问答、聊天、作业流程、注册找回、SSO、生产高可用。无需向量数据库、嵌入模型、异步任务集群或跨班级管理功能。

## Decisions

### 1. 教程技术栈与本地持久化

按用户提供的第3课教程技术栈约定，采用 Go 后端、MySQL 数据库、React 前端和 Nginx 入口。Go 使用 `net/http` 提供 API，通过 `database/sql` 与 MySQL 驱动访问数据库；React 构建产物由 Nginx 托管。选择该组合是为了与后续课程实现保持一致。

Compose 规划三个服务：Nginx、Go API、MySQL。浏览器通过 Nginx 同源访问 React 页面、`/api/` 和 `/health`；后两者保留路径转发到 Go，API 错误不能回退成 React 页面。仅 Nginx 向 localhost 暴露端口，Go 与 MySQL 使用内部网络。Nginx 不挂载上传文件卷，不提供材料静态下载；所有材料下载必须经过 Go 授权。代理请求体上限需容纳 5 MiB 文件及 multipart 开销，文件大小和业务错误由 Go 按规约校验。

MySQL 使用 InnoDB，数据目录 `/var/lib/mysql` 挂载独立命名卷 `mysql_data`；Go 的 `/data` 挂载 `material_data`，保存 `/data/uploads` 原文件与 `/data/staging` 临时文件。容器镜像和临时可写层不保存业务数据。数据库连接配置及密码从环境注入，不写入前端构建产物；Go 使用独立应用数据库账号，不使用 root 账号。

### 2. 身份、会话与密码

预置账号包含唯一用户名、带随机盐的 scrypt 密码哈希、角色（teacher/student）、单一班级外键。单账号单班级是本迭代的数据模型约定。密码通过后续初始化时的环境变量提供，禁止源码默认密码及明文落库，日志不得记录密码或会话凭据。

使用签名 Cookie 会话，仅携带用户标识和过期信息，每次请求从数据库重新读取角色与班级；不信任 Cookie 或请求中自报的角色/班级。会话有效期固定为登录后 8 小时，过期或签名错误返回 401。签名密钥从 `SESSION_SECRET` 环境注入，缺失或空值则启动失败，禁止开发默认值。Cookie 设置 HttpOnly、SameSite=Lax；课堂仅在 localhost HTTP 演示，HTTPS 环境启用 Secure。写操作需校验同源及 CSRF 令牌，登录页也提供相应保护。

选择签名会话而非自包含角色 JWT，是为了让授权信息始终来自服务端账号表。账号不存在和密码错误均返回相同 401 信息，不泄露账号存在性。

### 3. 接口与授权顺序

| 入口 | 行为 |
| --- | --- |
| `POST /api/login` | 校验用户名/密码，成功 200 并建立会话；失败 401 |
| `GET /api/materials` | 登录后返回本班列表，空列表为 200；无跨班级计数 |
| `POST /api/materials` | multipart 单文件上传，先认证再检查 teacher，成功 201 返回材料 ID |
| `GET /api/materials/{id}` | 返回本班材料元数据及关联提取文本 |
| `GET /api/materials/{id}/file` | 受保护下载原文件，以附件返回 |
| `GET /health` | 匿名可访问，仅返回健康状态；依赖可用为 200，否则 503 |

所有材料入口先检查身份，失败返回 401；上传再检查角色，学生返回 403，之后才处理文件。客户端提供的 `class_id`（查询串、表单或 JSON）以及角色参数一律不作为授权依据；忽略这些参数，以账号班级执行操作。教师 A 携带 B 班参数仍只能上传到 A 班。详情与下载使用 `id + 当前班级` 联合过滤，不存在或跨班均为同样的 404；不通过先查全局记录后返回差异错误来暴露存在性。

知识库不提供独立公开 API，只通过已授权的材料详情读取提取文本。文件不放在静态目录，不开放存储路径或直接下载 URL。React 最小页面提供登录、材料列表、教师上传和详情/下载，通过 Nginx 同源调用 Go API 并携带签名 Cookie 与请求保护令牌；隐藏学生上传入口只是交互提示，后端检查才是安全边界。

### 4. 上传合同与一致性

接受扩展名大小写不敏感的 `.txt`、`.md`，严格按 UTF-8（允许 BOM）解码。Markdown 提取文本定义为解码后的源码文本，不渲染为 HTML，不调用模型。单文件最大 5 MiB（5 × 1024 × 1024 字节）；非法类型 415，超限 413，缺文件/多文件/空白文本/非法编码 400。认证、授权优先于这些业务校验。客户端文件名仅保留安全展示名，存储名由服务端随机生成，不能包含用户指定路径。

数据表规划：classes；users（class_id、role、password_hash）；materials（id、class_id、uploader_id、original_name、storage_key、size、created_at）；knowledge_entries（id、material_id 唯一外键、extracted_text）。知识库班级通过材料关联确定，避免两份班级字段漂移。B 班预置材料允许 uploader_id 为空并标记为验收种子来源。

执行流程：授权 → 校验并写临时文件 → 解码提取 → 数据库事务内创建材料与知识库记录 → 将文件移动到持久目录 → 提交事务 → 返回 201。同步完成后列表即可读，无等待后台索引。任一步骤失败均不返回成功，不产生可见的半成品；存储/提取内部异常返回通用 500，数据库不可用返回 503，不泄露路径或异常堆栈。补偿删除失败时保留待清理文件，启动时清理 staging 与无数据库引用的文件，清理完成后再对外服务。事务提交成功但响应中断时记录仍有效；重复提交视为独立上传，本迭代不提供去重或幂等键。

选择数据库事务加文件补偿，而非宣称文件系统与数据库原子提交；Go 在同一个 MySQL InnoDB 事务中写入两类记录，启动清理解决提交前崩溃产生的孤儿文件。MySQL 提交时若连接中断导致结果不确定，必须按本次服务端生成的材料 ID 重新核实提交结果；无法核实时保留文件并返回 503，待数据库恢复后核实再清理，不能误删已提交记录引用的文件。

### 5. 健康检查、配置与样本

Go 的 `GET /health` 检查 MySQL 连接及材料数据目录读写能力，只返回 `ok` 或 `unavailable` 状态，不输出材料、用户、配置或密钥。Nginx 将匿名健康请求代理到 Go；Go 不可达时，Nginx 对该入口统一返回 503 和 `unavailable` 状态。Compose 分别检查 MySQL 就绪、Go 健康和 Nginx 对外健康入口；Go 在数据库就绪后执行结构初始化与文件恢复，再对外提供业务服务。启动要求环境密钥与数据库连接配置齐全，开发种子初始化另需三个账号密码。后续 `.env.example` 仅写变量名/占位说明；真实 `.env` 不提交。

验收数据由显式开发初始化步骤创建：A/B 两班；`teacher_a`（教师 A，A 班）、`student_a1`（学生 A1，A 班）、`student_b1`（学生 B1，B 班）。三者密码由环境分别注入，重复初始化不得重置账号密码或重复插入材料。B 班通过种子直接入库，不增加教师 B 或绕过学生上传限制的 API。

| 样本 | 用途 | 可辨识文本 |
| --- | --- | --- |
| `class-a-intro.txt` | 教师 A 实际上传 | `CLASS_A_TXT_ONLY` |
| `class-a-notes.md` | 教师 A 实际上传 | `# A notes` 与 `CLASS_A_MD_ONLY` |
| `class-b-seed.txt` | B 班预置材料、原文件及知识库记录 | `CLASS_B_SEED_ONLY` |

本轮仅规定样本名称和内容标记，样本文件与种子程序留待实现阶段生成。验收双向验证 A 看不到 B、B 看不到 A，不能用空 B 班列表代替隔离验证。

## Risks / Trade-offs

- 文件与数据库不能共同事务提交 → 返回成功前完成全部步骤；失败补偿与启动孤儿清理，并注入失败验证。
- MySQL 增加启动依赖及网络故障情形 → 健康检查、连接超时与事务结果核实；维持单个 Go 实例，生产高可用不在范围内。
- Nginx 代理可能改写 API 路径、错误码或绕过材料权限 → 保留 API 路径和错误响应，只托管 React 静态资源，端到端验收通过 Nginx 执行。
- Markdown 中可能包含脚本样式文本 → 只以转义文本显示，下载使用附件方式。
- 误删命名卷将丢失数据 → 文档区分正常停止/重建与显式删除卷；验收不使用删除卷选项。
- 密钥更换使现有会话失效 → 重新登录；持久化数据与账号哈希保持有效。

## Migration Plan

本轮不执行部署。后续阶段构建 Go 可执行文件与 React 静态产物，配置 Nginx 路由，创建两个命名卷并等待 MySQL 就绪后初始化数据库结构，再从环境初始化验收账号和 B 班种子，由教师 A 经 Nginx 上传两个样本。验证停止并重建全部容器（保留两个命名卷）后账号、材料原文件、文本关联仍在。当前尚无应用和旧数据，无需数据库格式转换；后续升级前暂停写入，制作一致的 MySQL 备份与上传目录备份，失败时恢复匹配版本的镜像与数据备份，不删除卷。
