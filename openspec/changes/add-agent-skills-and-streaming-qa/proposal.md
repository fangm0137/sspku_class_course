# Proposal: 智能体、技能与流式问答

## Why

第 4 课把本班材料切分、向量化并能检索出带出处的切片，但检索结果只是"一次性返回"：没有角色设定、没有可复用的引导规程、也不能连续追问。本课把三件事接进**同一次回答**——教师配置的**提示词**（这个助手是谁）、**技能**（这一题按什么规程引导）、**知识库**（依据来自哪几份材料）——并把回答改为 SSE 流式逐段推送，使一个可持续多轮的教学助手成立。

## What Changes

- **智能体**：教师在班内创建、修改、启停智能体，为每个智能体绑定技能与本班材料（两张关联表）；班级隔离与"跨班即不存在"沿用既有口径。
- **技能**：教师以单个文本文件定义技能（元数据区 + 引导规程），服务端解析校验后入库；提供增删改查，写操作仅教师、班内名称唯一。
- **技能路由**：在"该智能体绑定且已启用"的候选集内做**服务端词法计分**（适用条件切词 + 子串命中），取最高分一条，同分取编号较小者，零分不选技能；不调用模型。
- **会话与消息**：新增 `conversations` 与 `messages` 两张表；新建会话必须选定本班一个已启用的智能体并永久锁定；上下文固定取末尾 6 条消息、每条截断 500 字。
- **流式回答**：新增 SSE 问答接口，事件分 `meta`（先带技能与引用列表）、`delta`（增量文本）、`done`（助手消息编号）、`error`；系统消息只放提示词与技能，**资料放用户消息**；引用编号连续且与引用列表一一对应。
- **口径变化**：检索落空或该智能体未绑定材料时**不再回固定文案**，改按智能体提示词照常作答，引用列表为空、正文不出现 `[n]`；第 4 课的 `POST /api/ask` 保留原口径，两条路径并存。
- **接口文档**：提供 OpenAPI 描述与 Swagger 页面，可对照文档试调主要接口。
- **部署**：Nginx 对问答路径关闭代理缓冲（`proxy_buffering off`、`proxy_cache off`、读超时放宽），服务端每帧 `Flush` 并返回 `X-Accel-Buffering: no`。
- **前端**：教师侧增加智能体与技能的管理入口；学生侧增加会话列表、选定智能体新建会话、`fetch` 解帧逐段渲染与引用展示。

## Capabilities

- `tutor-agents`：智能体的字段、班级隔离、启停语义与两份绑定。
- `agent-skills`：技能文件的解析与校验、班内 CRUD、词法路由计分。
- `conversations`：会话与消息的存储、归属判定、智能体锁定与上下文窗口。
- `streaming-answers`：三路输入的一次回答、落空口径、SSE 四类事件与持久化。
- `api-reference`：可访问的 OpenAPI 文档与试调入口。

## Impact

- **新增表**：`tutor_agents`、`tutor_agent_skills`、`tutor_agent_materials`、`skills`、`conversations`、`messages`（迁移 `000005`）。
- **新增接口**：智能体、技能、会话、消息与流式问答（详见 design 的接口表）。
- **改动既有文件**：路由注册、Compose 的 Nginx 配置、前端主视图与 API 客户端。
- **不改动**：`class-material-access`（认证、材料、班级隔离）与 `knowledge-qa`/`knowledge-retrieval`（切分、检索、`/api/ask`、重建索引）的既有行为合同；第 4 课的问答接口保留原样，本课的流式回答是并列的新入口。

## Non-Goals

- 不实现 WebSocket、多端协作或双向实时通道；不实现 SSE 的断点续传与事件重放。
- 不让模型自主选择技能（路由是确定性的服务端计分），不引入技能市场、跨班共享或版本管理。
- 不做流式中途重试与增量落库；生成中途失败时以已产出内容收尾。
- 不实现刷新令牌、限流、会话级撤销（沿用第 4 课的认证口径）。
- 不把资料正文放进系统消息，也不为提示词注入做内容过滤（只做位置隔离与边界声明）。
