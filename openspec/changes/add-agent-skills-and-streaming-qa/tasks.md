# Tasks

本变更处于规约阶段：以下任务均保持未勾选，逐项实现并执行 verify 后才勾选，不把文档生成当作功能实现。第 4 课的认证、材料、检索与 `/api/ask` 已归档为基线，本课在其之上追加"智能体 + 技能 + 流式回答"，不改动既有行为合同。后端预定目录 `backend`，前端 `frontend`。

顺序按依赖关系：数据模型 → 智能体与技能 → 会话与消息 → 路由与消息组装 → 流式问答 → 接口文档与部署 → 前端 → 端到端验收。故障注入在应用边界进行（把对话网关指向不可达地址、停掉向量库、制造超长/越界输入），不用删除真实数据模拟。

## 1. 数据模型与种子

- [ ] 1.1 新增迁移 `000005`：`tutor_agents`（班内名称唯一、长度 CHECK、班级外键）、`tutor_agent_skills`、`tutor_agent_materials`（联合主键 + 级联删除）、`skills`（班内名称唯一、长度 CHECK、`subject_text` 可空、`seed_key` 幂等键）、`conversations`（`agent_id` 非空、`(user_id,updated_at)` 索引）、`messages`（`role` 枚举、级联删除、`(conversation_id,id)` 索引）；up/down 都写。
  verify：真实 MySQL 8.0 上两次 `migrate up`（第二次 `no change`）、`SHOW CREATE TABLE` 核对列/唯一键/索引/外键/CHECK；重复名称、超长字段、跨班 `agent_id`、非法 `role` 逐项被拒且不留痕。
- [ ] 1.2 A 班预置两份技能（数学解题引导、语文解题引导）：以 `seed_key` 保证幂等，重复执行 `no change`；文件原文写入 `source_text`，可在编辑接口取回。
  verify：重复执行两次，技能行数与字段不变；`source_text` 与预置文件逐字一致。

## 2. 智能体与技能

- [ ] 2.1 智能体读写与两份绑定：名称 ≤64 且班内唯一、提示词 ≤2000 可为空、启停；绑定只接受本班技能与本班材料，整体替换语义。
  verify：教师创建两个智能体并各绑不同技能与材料；学生调用写接口 403；按编号访问他班或未启用智能体返回与不存在完全一致的 404；提示词留空时回答回退默认角色。
- [ ] 2.2 技能文件解析与校验：空行分界、五个中文键行、`#` 与空行忽略、未知/重复/缺字段拒绝、工具只接受 `knowledge_search`、长度上限（整体 8000 / 名称 32 / 适用条件 120 / 说明 2000 / 资料 32），错误信息面向教师可读。
  verify：单元测试覆盖每种拒绝原因；接口层提交非法文件返回 400 且带字段名；合法文件入库后各列与文件逐项对应。
- [ ] 2.3 技能增删改查：班内名称唯一（同名 400）、写操作仅教师、按编号跨班取 404、停用后不参与路由；读取接口返回 `source_text`。
  verify：逐项请求并记录状态码；停用某个仍被绑定的技能后，路由结果改变。

## 3. 会话与消息

- [ ] 3.1 会话接口：新建必须选定本班已启用智能体（否则 404）、本班无已启用智能体返回 400、`agent_id` 建时写入且此后不可改、标题占位串 → 首轮前 24 字、`updated_at` 每轮刷新、列表按更新时间倒序。
  verify：新建/读取/列表逐项实测；消息体里再带其他智能体编号时回答仍按原智能体；停用智能体后已有会话仍可提问。
- [ ] 3.2 会话归属判定与跨班隔离：他人会话、他班会话、不存在编号三种情形返回完全一致的 404；未登录 401；列表按用户过滤。
  verify：两账号交叉读取，比对响应体逐字节一致；用 SQL 核对列表只返回自己的会话。
- [ ] 3.3 消息读写与上下文窗口：用户/助手两条消息按序落库，助手消息带引用列表与技能名；窗口取末尾 6 条、每条截断 500 字、跳过非法角色与空正文；本轮提问先落库因而在窗口内。
  verify：构造超过 6 条消息的会话，断言进入上下文的条数与截断长度；读取接口仍能看到更早的消息。

## 4. 路由与消息组装

- [ ] 4.1 路由计分：候选集＝该智能体绑定且启用；适用条件按中英文逗号/顿号/分号/竖线切词；子串命中每词 1 分；两侧小写折叠；取最高分、同分取编号较小者；零分不选；至多一条。
  verify：单元测试覆盖"最高分胜出""同分取小编号""零分不选""未绑定不参与""大小写折叠"；接口层用两份可同时命中的技能断言系统消息里只有一份引导正文。
- [ ] 4.2 消息组装：系统消息按固定段序（提示词 → 技能段含「解题引导」硬性要求 / 未命中提示 → 资料口径 → 不提模型 → 边界句），资料放用户消息（每条截断 800 字、先剔除后编号），历史末尾 6 条。
  verify：单元测试断言系统消息不含任何资料正文；断言命中「解题引导」时系统消息含"不写得数"类硬性要求；断言编号连续无跳号。

## 5. 流式问答

- [ ] 5.1 对话网关流式调用：沿用既有网关客户端新增底层 `ChatStream`（`stream: true`、逐行解析 `data:` 帧、遇到 `[DONE]` 结束），非 2xx、超时与解析失败统一归为依赖不可用。
  verify：单元测试用本地假上游覆盖正常流、中途断开与非 2xx；真实网关实测能收到多个增量片段（若上游不支持流式，改记"模拟流式"口径）。
- [ ] 5.2 SSE 接口 `POST /api/conversations/{id}/messages`：四类事件 `meta`/`delta`/`done`/`error`；三个响应头 + `X-Accel-Buffering: no`；每帧 `Flush`；`delta` 为增量、拼接等于终稿；助手消息连同引用与技能名落库、`done` 返回其编号。
  verify：用 `curl -N` 抓流并断言事件顺序与拼接结果；断言响应头齐全；断言 `done` 的编号能在消息表查到对应行。
- [ ] 5.3 流前失败与流后失败的分工：鉴权、会话归属、班级比对、检索依赖可用性在写第一帧前完成 → 401/404/503；进入生成后失败以 `error` 收尾且状态 200；已产出片段后失败以已产出内容收尾并落库。
  verify：分别注入"未登录""不存在会话""停掉向量库""把对话网关指向不可达地址"，记录状态码与事件；断言部分失败时已产出的文本被落库。
- [ ] 5.4 落空口径与编号剥离：检索无候选或未绑定材料时仍调用模型；引用列表为空数组；推送前剥掉正文中的 `[n]`（带缓冲过滤，避免跨帧漏判）。
  verify：用与本班材料无关的提问实测：回答照常生成、`citations` 为空、正文无编号；对照第 4 课 `/api/ask` 同一问题仍返回固定文案且不调模型。

## 6. 接口文档与部署

- [ ] 6.1 OpenAPI 与 Swagger：`internal/httpapi/openapi.go` 维护与路由同源的注解表，启动时生成 `/openapi.json`；`/swagger` 页面渲染接口清单并支持试调。
  verify：浏览器打开 `/swagger` 能看到接口清单；按文档对一个受保护接口发起试调成功；文档内容不含任何密钥、令牌或内部路径。
- [ ] 6.2 部署调整：Nginx 对问答路径 `proxy_buffering off`、`proxy_cache off`、读超时放宽；Compose 环境变量与文档同步（若有新增）。
  verify：`nginx -t` 或容器启动无错；经 Nginx 抓包可见多次 `delta`；把 `proxy_buffering` 恢复默认后文字变为一次性出现（反向证明缓冲是必要条件）。
