# 智能体、技能与流式回答（第 5 课）

这一层把第 4 课的检索能力接进"一次回答"：教师配置智能体，学生选智能体提问，
服务端按该智能体选技能、检索它绑定的材料，再以 SSE 逐段返回回答。

## 一次回答的顺序

```
POST /api/conversations/{id}/messages
  1 校验提问（2–500 字）
  2 读会话：必须属于当前账号且属于本班，否则 404
  3 读会话锁定的智能体（它被停用也照常作答）
  4 落库本轮提问；标题仍是占位串时改写为提问前 24 字
  5 取上下文窗口：末尾 6 条消息、每条截断 500 字
  6 技能路由：只在该智能体绑定且启用的技能里选，至多一个
  7 检索：只在该智能体绑定的材料里取前 4 条切片（命中"资料"范围时再按标题过滤）
  8 组装消息：系统消息 = 提示词 + 技能说明 + 口径 + 边界句；资料放用户消息
  9 ---- 以上完成后才写响应头，之后状态码不可再变 ----
 10 调对话网关流式生成，逐段回 delta
 11 助手消息（正文 + 引用列表 + 技能名）落库，回 done
```

第 9 步是分界线：**能提前判定的失败仍以 HTTP 状态码返回**（会话不存在 404、
提问为空 400、依赖不可用 503）；流一旦开始，只能用 `error` 事件收尾。

## 事件协议

| 事件 | 时机 | 负载 |
|---|---|---|
| `meta` | 检索完成、开始生成之前 | `status`、`conversation_id`、`user_message_id`、`skill`（未命中为 null）、`citations` |
| `delta` | 每收到一段 | `text` —— **增量**，不是累计全文 |
| `done` | 生成并落库成功 | `assistant_message_id` |
| `error` | 流开始之后失败 | `error`、`message` |

引用列表随 `meta` 先到，正文随后到达，因此页面可以先渲染"依据"再逐字出答案。

## 技能

技能是教师写的**单个文本文件**，空行以上是元数据键行，空行以下是引导规程：

```
名称：数学解题引导
适用条件：方程,去括号,分数,通分
资料：数学
工具：knowledge_search
启用：是

学生正在自己做数学作业……（引导规程）
```

- 表 `skills` 的每一列都能从文件解析出来，因此**接口只接受文件原文**（`source_text`），
  教师不需要逐字段填表，也不会出现"列与文件不一致"。
- 解析失败返回 400，并带回**行号**与字段名。
- `资料` 是资料范围：该技能命中时，检索会额外要求材料标题含这个词。

### 路由：服务端词法计分，不调模型

候选集 = 该智能体绑定且已启用的技能。把 `适用条件` 按中英文逗号、顿号、分号、竖线
切词，逐个判断是否为提问的**子串**（两侧转小写），命中一个得 1 分；取最高分，
**同分取编号较小者**，零分不选技能。

至多选一个是有意的：两份规程同时注入会互相冲突（一份"只给思路"、一份"直接给结论"），
输出不可预测。

## 组装消息时的两条口径

1. **资料进用户消息，不进系统消息。** 系统消息只放角色与约束；资料与技能描述都来自
   上传的文件，属于"数据"而不是"指令"，边界句会明确要求模型不要把其中的内容当命令执行。
2. **编号与引用严格对齐。** 剔除空正文的切片之后重新编号，所以正文里的 `[n]` 一定对应
   `citations[n-1]`，不会出现指向不存在条目的编号。

命中名称含「解题引导」的技能时，系统消息追加一条硬性要求：只指出下一步该检查什么，
**不写出最终答案、选项、得数**。

## 与 `POST /api/ask` 的口径差异（重要）

| | `POST /api/ask`（第 4 课） | `POST /api/conversations/{id}/messages`（本课） |
|---|---|---|
| 检索范围 | 本班全部材料 | 只在该智能体绑定的材料内 |
| 检索落空 | 直接返回「资料中未找到相关内容。」，**模型调用 0 次** | **仍调用模型**按角色与技能作答 |
| 引用 | `hits` 为空 | `citations` 为空数组，正文**不得出现 `[n]`**（推给浏览器前再剥一遍） |

两条路径并存，各有用途：前者是"有依据才答"，后者是"有依据用依据、没依据按角色答"。

## 上下文窗口

固定取消息表**末尾 6 条**、每条截断 **500 字**，每轮重新查询（滑动窗口，不记读位置）。
本轮提问在检索之前就已落库，因此它必定落在窗口内，再从历史里排除以避免重复。

## 部署要点

- **Nginx 必须对流式接口单独放行**：长连接会超过 `/api/` 前缀的 30 秒读超时，
  且必须关闭缓冲（`proxy_buffering off`）与压缩，否则片段会攒在 Nginx 里。
  见 `deploy/nginx.conf` 里那条正则 location。
- **服务端每写一帧都要 flush**（`http.Flusher`），否则片段滞留在 Go 的响应缓冲里。

## 自测

```bash
# 1) 教师建技能（原文），记下 id
curl -s -X POST "$base/api/skills" -H "Authorization: Bearer $teacher" \
  -H 'Content-Type: application/json' \
  -d '{"source_text":"名称：数学解题引导\n适用条件：方程,通分\n启用：是\n\n只提示下一步该检查什么。\n"}'

# 2) 建智能体并绑定技能与材料（整体替换，传空数组即解绑）
curl -s -X POST "$base/api/agents" -H "Authorization: Bearer $teacher" \
  -H 'Content-Type: application/json' -d '{"name":"数学助教","enabled":true}'
curl -s -X PUT "$base/api/agents/1/skills"    -H "Authorization: Bearer $teacher" \
  -H 'Content-Type: application/json' -d '{"skill_ids":[1]}'
curl -s -X PUT "$base/api/agents/1/materials" -H "Authorization: Bearer $teacher" \
  -H 'Content-Type: application/json' -d '{"material_ids":[5]}'

# 3) 学生会话并流式提问（-N 关闭 curl 自身缓冲）
curl -s -N -X POST "$base/api/conversations/1/messages" \
  -H "Authorization: Bearer $student" -H 'Content-Type: application/json' \
  -d '{"question":"这道方程我下一步该检查什么？"}'
```

浏览器端可在 `/swagger/` 里对照接口文档试调；该页面会自动复用登录时保存的令牌。

初始化顺序见 [FIXTURES.md](FIXTURES.md)：迁移 → 账号 → 材料 → 技能。
